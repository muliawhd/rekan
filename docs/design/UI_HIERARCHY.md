# Re:kan — UI_HIERARCHY.md

## 1. Global hierarchy rule

Each screen should have:

1. one dominant screen purpose,
2. one primary action,
3. secondary actions,
4. supporting metadata.

Do not allow metadata to compete with the primary decision.

## 2. Discover card hierarchy

Priority order:

### Level 1 — Identity
- name
- university
- program
- semester

### Level 2 — Collaboration relevance
- primary skills
- active courses
- project/competition role
- collaboration goal

### Level 3 — Context
- availability
- study mode
- short bio
- interests
- portfolio preview

### Level 4 — Actions
- Lewati
- Simpan
- Detail
- Ajak Kolaborasi

The main card should not show every profile field.

## 3. Profile detail hierarchy

1. Identity block
2. Primary collaboration CTA
3. About
4. Skills
5. Active courses
6. Study preferences
7. Portfolio
8. Secondary metadata

## 4. Chat inbox hierarchy

1. Screen title
2. Search/filter
3. Category tabs
4. Unread conversations
5. Recent conversations
6. Rooms

Unread state must be obvious but not overpowering.

## 5. Room hierarchy

1. Room identity
2. Room purpose / pinned context
3. Active mode tab
4. Content
5. Composer / primary interaction

Tasks/files/notes should not visually dominate normal conversation unless explicitly selected.

## 6. Academic profile hierarchy

1. Identity summary
2. Edit profile action
3. Academic information
4. Skills
5. Interests/topics
6. Availability
7. Portfolio or proof of work

## 7. Onboarding hierarchy

Every onboarding step should contain:

- progress context,
- one short title,
- one concise explanation,
- the minimum fields needed for that step,
- Back / Continue controls.

Avoid full-page forms.

## 8. Content density

Discover:
- low-to-medium density

Profile:
- medium density

Chat:
- medium-to-high density

Onboarding:
- low density

Room:
- medium density

## 9. Section spacing

- Inside a component: 8–16
- Between related components: 16
- Between sections: 24–32
- Major hero separation: 32–48

## 10. Alignment

Use a strong grid.

- Main content aligns to one left edge.
- Chips align to their section, not card edges randomly.
- Metadata uses consistent rows.
- Buttons should not float without alignment rationale.
